カスタムデータ用RAGプロンプトの書き方

対象：全ユーザーカスタムデータを使えるプランのご契約でのみ使えます

カスタムデータを使うモードで、検索した資料をAIにどう使わせるかを決める「カスタムデータ用RAGプロンプト」の書き方を、簡単な形から順に説明します。

「カスタムデータ用RAGプロンプト」は、カスタムデータを検索して見つかった資料を、AIにどう使わせるかを指示する文章です。たとえば「資料に書かれていないことは答えない」「表にまとめる」「必ずファイル名を書く」といった決まりを、モードごとに決められます。

書かなくても、POPstationが用意した既定の指示文で動きます。既定の動きで足りないときだけ書き換えます。

始める前に

  • カスタムモードの作成・編集の画面で、「データ参照先」を「カスタムデータ」にすると、「カスタムデータ用RAGプロンプト」の欄が折りたたまれた状態で表示されます（モードの作成・編集）。
  • 欄には、最初から既定の指示文が入っています。欄に手を加えずに保存すると、既定の指示文が使われます。 欄を空にして保存したときも同じです。
  • 検索から回答までの流れは、カスタムデータ検索（RAG）のしくみにあります。先に読むと、この先が分かりやすくなります。

しくみを1分で

カスタムデータを使うと、POPstationは質問のたびに次のことをします。

  1. 質問に関係しそうな資料の断片を、検索で最大10件探す
  2. このページで書く指示文に、質問と見つけた断片を差し込む
  3. できあがった文章をAIに送る

AIが見られるのは、2.で差し込まれた断片だけです。指示文は、その断片を「どう読んで、どう答えるか」をAIに伝える役目です。

必ず入れる2つの語

指示文には、次の2つの語を必ず入れます。どちらかが無いと、保存のときに「カスタムデータ用RAGプロンプトに {search_query} が含まれていません」（{search_result} も同じ）と表示され、保存できません。

語AIに送るときに入るもの
{search_query}質問の文（モードでは、入力欄の値を差し込んだあとのモードプロンプト）
{search_result}検索で見つけた資料の断片。断片ごとに「Ref: ファイル名」の行と本文が並びます

欄の下の「{search_query}」「{search_result}」のボタンを押すと、カーソルの位置にその語が入ります。半角の波かっこ { } と、つづりを正確に書いてください。

例：{search_result} は、AIに送るときに次のような文字に置き換わります。

Ref: 旅費規程.pdf
第3章 旅費 ＞ 第12条（日当）
国内出張の日当は、1日につき2,000円とする。

Ref: 出張申請の手引き.docx
日当は精算時に自動で計上されます。…

ステップ1：いちばん簡単な形

まずは、2つの語を入れただけの短い形から始めます。

次の資料をもとに、質問に答えてください。

質問：{search_query}

資料：
{search_result}

これでも動きます。「出張の日当はいくらですか？」と質問すると、AIには次の文章が届きます。

次の資料をもとに、質問に答えてください。

質問：出張の日当はいくらですか？

資料：
Ref: 旅費規程.pdf
第3章 旅費 ＞ 第12条（日当）
国内出張の日当は、1日につき2,000円とする。
…

ステップ2：守ってほしい決まりを足す

簡単な形のままだと、資料に無いことをAIが自分の知識で補って答えることがあります。守ってほしい決まりを、箇条書きで足します。

次の資料をもとに、質問に答えてください。

# 決まり
- 資料に書かれていることだけで答える
- 資料に書かれていないときは「資料に記載がありません」とだけ答える
- 推測で数字や日付を補わない

質問：{search_query}

資料：
{search_result}

決まりは短く、具体的に

「正確に答えて」のようなあいまいな指示より、「資料に無いときは『資料に記載がありません』と答える」のように、どういうときに、何をするかを書くほうが守られます。

ステップ3：回答の形を決める

回答の形（表・箇条書き・長さ）を決めると、毎回そろった回答になります。

# 出力の形
- 最初に1〜2行で結論を書く
- 続けて、根拠を箇条書きで3つまで書く
- 全体で300文字以内にする

表にしたいときは、列を決めて書きます。表の書き方はマークダウン記法の基本もご覧ください。

# 出力の形
次の列の表にまとめる：項目 / 内容 / 根拠のファイル名

ステップ4：根拠の示し方を決める

回答を確かめやすくするために、根拠のファイル名を書かせます。断片には「Ref: ファイル名」の行があるので、それを使うように指示します。

# 根拠
- 回答の根拠にした資料のファイル名を、「Ref:」の行から書き写す
- 資料の文をそのまま使うときは、引用（>）で示す

書き換えると、ページ番号は付かなくなります

既定の指示文を使っているときは、断片の「Ref:」の行にページ番号（例：p.12）も付き、回答にページ番号まで書かれます。欄を書き換えて自分の指示文を使うと、「Ref:」の行にはファイル名だけが入り、ページ番号は付きません。 指示文に「ページ番号を書く」と書いても、AIにはページ番号が渡っていないので書けません。ページ番号が必要なときは、既定の指示文のまま使います。

ステップ5：役割と読み手を伝える

誰が読む回答なのかを伝えると、言葉づかいや詳しさがそろいます。

# 役割
あなたは総務部の担当者です。社員からの規程の問い合わせに、やさしい言葉で答えます。

完成例

ここまでを組み合わせた例です。用途に合わせて書き換えてください。

例：社内規程の問い合わせに答える

# 役割
あなたは総務部の担当者です。社員からの社内規程の問い合わせに答えます。

# 決まり
- 資料に書かれていることだけで答える
- 資料に書かれていないときは「規程に記載がありません。総務部にお問い合わせください。」とだけ答える
- 金額・日数・期限は、資料の表記のまま書く

# 出力の形
- 最初に1〜2行で結論を書く
- 続けて、根拠になった条文を引用（>）で示し、その上にファイル名を書く

# 質問
{search_query}

# 資料
{search_result}

例：お客さまへの回答の下書きを作る

# 役割
あなたはサポート窓口の担当者です。お客さまへのメールの下書きを作ります。

# 決まり
- 資料（製品マニュアル・FAQ）に書かれていることだけを使う
- 資料に無い内容は書かず、最後に「確認が必要な点」として箇条書きにする
- 敬語で、お客さまに分かる言葉で書く

# 出力の形
件名・本文の順で書く。本文は400文字以内。

# お客さまからの問い合わせ
{search_query}

# 資料
{search_result}

例：議事録や報告書から情報を集める

次の資料から、質問に関係する情報を集めて表にしてください。

# 決まり
- 資料に書かれていることだけを使う
- 日付と決定事項は、資料の表記のまま書く
- 該当する情報が無い資料は、表に入れない

# 出力の形
次の列の表にする：日付 / 決まったこと / 担当 / ファイル名

# 質問
{search_query}

# 資料
{search_result}

この例のように「集めて表にする」使い方では、AIに渡る断片は多くても10件です。資料の全体を漏れなく集めたいときは、カスタムデータではなく、ファイルを添付して質問します（カスタムデータ検索（RAG）のしくみ）。

よくある間違い

書き方起きること直し方
{search_result} を書き忘れる保存できません（「…{search_result} が含まれていません」）欄の下のボタンで入れます
{ search_query }（空白入り）、｛search_query｝（全角）、{search-query}必須の語と見なされず保存できないか、置き換わらずにそのままAIに届きます半角で、空白を入れずに書きます。ボタンで入れると確実です
指示文の中に、ほかの {名前} を書く置き換わらずに、そのままの文字でAIに届きます（エラーにはなりません）波かっこを使わない書き方にします
「資料をすべて読んで答えて」と書くAIに渡るのは検索で選んだ断片だけなので、すべては読めません「資料に無いときは〜と答える」と書きます
「ページ番号を書いて」と書く書き換えた指示文ではページ番号が渡らないので、書けませんページ番号が要るときは既定の指示文を使います
モードプロンプトに長い指示を書くモードではモードプロンプトの全文で検索するので、指示の言葉に引っぱられて、関係の薄い資料が見つかることがあります出力の形などの指示は、モードプロンプトよりRAGプロンプトに書きます

{search_query} と {search_result} のほかに、{prompt} と {user_query} も、質問の文に置き換わります。

既定の指示文（参考）

欄に最初から入っている既定の指示文には、次のことが書かれています。書き換えるときは、これをもとにしてください。

部分内容
役割高度な分析能力と専門知識を持つAIアシスタント
指示参照ファイルの情報を使って質問に答える
手順要点をまとめてから詳しく説明する／引用はブロック引用（>）でファイル名とページ番号を書く／確信度を示す／参照ファイルに無いことを推測で補わない／していないこと（「画像を直接確認した」など）を根拠として書かない／画像から自動で作られた説明の部分は、引用せず「（画像）」とだけ書く
出力形式Markdown形式・重要な部分は強調・日本語

うまくいかないとき

困っていること確かめること
「参考情報が見つかるような…」と表示される指示文ではなく検索の問題です。質問やモードプロンプトに、資料の言葉が入っているか確かめます（カスタムデータを上手に使うコツ）
資料に無いことまで答える「資料に無いときは〜と答える」の決まりを足します
回答の形がそろわない出力の形を、列名や文字数まで具体的に書きます
前より回答の質が下がった欄を空にして保存すると、既定の指示文に戻ります
前へモードプロンプトの書き方次へカスタムデータを上手に使うコツ
