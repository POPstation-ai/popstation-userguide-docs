モードプロンプトの書き方

対象：全ユーザー

モードプロンプトに入力欄を作る書き方（#{…}）と、使いやすいモードにするコツです。

モードプロンプトは、モードを実行したときにAIに送る指示の文章です。文章の中に #{…} を書くと、そこが入力欄になります。モードを実行する人が入力欄に入れた値は、#{…} の位置に差し込まれてAIに送られます。

モードを作る手順はモードを作る、画面の項目はモードの作成・編集をご覧ください。

基本の形

#{title: "入力欄の名前", type: "text"}
項目内容必須
title入力欄の名前です。実行の画面に表示されます。1つのモードの中で、同じ名前は使えません必須
type入力欄の種類です（下の表）必須

入力欄の種類

type実行の画面書き方の例
text1行の入力欄#{title: "会社名", type: "text"}
multi-line-text複数行の入力欄#{title: "議事録の本文", type: "multi-line-text"}
select選択肢から選ぶ欄（プルダウン）。選択肢は options に並べます#{title: "文体", type: "select", options: ["です・ます調", "である調"]}

入力欄に付けられる設定

項目内容書き方の例
optional入力しなくても実行できる欄にします。付けないと必須の欄になり、空のままでは「入力してください」（選択肢の欄は「選択してください」）と表示されます#{title: "補足", type: "text", optional: "true"}
description入力欄の説明を表示します#{title: "文字数", type: "text", description: "半角数字で入力します"}
default最初から入っている値です#{title: "文字数", type: "text", default: "400"}
placeholder選択肢の欄（select）だけで使えます。最初は何も選ばれていない状態にし、この案内を表示します。付けない場合は、最初の選択肢が選ばれた状態になります#{title: "部署", type: "select", options: ["営業", "総務"], placeholder: "選択してください"}
dependsOnほかの入力欄の値によって、この入力欄を表示するかどうかを変えます#{title: "理由", type: "text", dependsOn: {fieldIndex: 0, values: ["いいえ"]}}

dependsOn の fieldIndex は、何番目の入力欄の値を見るかを表します。1つ目の入力欄が0です。上の例は、1つ目の入力欄で「いいえ」を選んだときだけ「理由」を表示します。

書き方の決まり

  • 値は "…" か '…' で囲みます。
  • 項目の名前（title など）のすぐ後ろに「:」を書きます。間に空白を入れると、エラーになります。例：title : "会社名" はエラーです。
  • 使える項目の名前は、上の表にあるものだけです。ほかの名前を書くと「不正なプロパティ '…' が検出されました。」と表示されます。つづりが近い名前があるときは、「'…' の誤りではありませんか。」と候補も表示されます。
  • #{ と } の数をそろえます。そろっていないと「…番目の#{ }プレースホルダーで括弧の対応が取れていません。…」と表示されます。

サンプル記入のボタン

モードプロンプトの欄の下のボタンを押すと、入力欄の書き方がモードプロンプトのカーソルの位置に入ります。文字を選んでいるときは、その文字と置き換わります。欄に一度もカーソルを置いていないときは、プロンプトの最後に入ります。

ボタン入る内容
「テキストボックス」#{title: "テキストボックス", type:'text'}
「複数行のテキストボックス」#{title: "複数行のテキストボックス", type:'multi-line-text'}
「プルダウン」#{title: "プルダウン", type: 'select', options:['A', 'B', 'C', 'D', 'E']}
「プルダウン（初期未選択）」#{title: "プルダウン（初期未選択）", type: 'select', options:['A', 'B', 'C'], placeholder: '選択してください'}
「任意記述」#{title: "任意記述", type:'text', optional: 'true'}
「説明の記述」#{title: "説明の記述", type:'text', description: 'ここに説明を記述します'}
「初期値の指定」#{title: "初期値の指定", type:'text', default: 'ここに初期値を記述します'}
「条件表示」#{title: "条件表示", type:'select', options:['X', 'Y', 'Z'], dependsOn: {fieldIndex: 0, values: ['A', 'B']}}

入ったあとで、title と選択肢をモードに合わせて書き換えます。

書けたらフォーマットチェック

ボタンの段の下にある「フォーマットチェック」を押すと、書き方の誤りを調べます。

  • 誤りが無いと「エラーは検出されませんでした。」と表示されます。
  • 誤りがあると「… 件の文法エラーが見つかりました。」と、誤りのある行（「… 行目」）と内容が表示されます。
  • 誤りがあるままでは、モードを保存できません。

例：議事録を要約するモード

次の議事録を、#{title: "読み手", type: "select", options: ["部長", "チーム全員", "取引先"]}向けに要約してください。
決まったこと・宿題・期限の3つの見出しで、箇条書きにしてください。
全体で#{title: "文字数", type: "text", default: "400", description: "半角数字で入力します"}字程度にしてください。
#{title: "特に強調したい点", type: "text", optional: "true"}

議事録:
#{title: "議事録の本文", type: "multi-line-text"}

実行の画面には「読み手」「文字数」「特に強調したい点」「議事録の本文」の4つの入力欄が並びます。

使いやすいモードにするコツ

  • 毎回同じ指示（目的・出力の形・守ってほしいこと）は、入力欄にせず文章として書きます。変わる部分だけを入力欄にします。
  • 選ぶ値が決まっているものは select にします。入力のゆれが減り、回答がそろいます。
  • 入力の仕方に迷いそうな欄には description を付けます。
  • よく使う値は default に入れておくと、入力の手間が減ります。
  • プロンプトの文章を実行する人に見せるかどうかは、「オリジナルプロンプトの表示」で決められます。
  • カスタムデータを参照するモードでは、「カスタムデータ用RAGプロンプト」で、検索の結果をAIに渡すときの指示を変えられます。書き方は、簡単な形から順にカスタムデータ用RAGプロンプトの書き方で説明しています。
  • カスタムデータを参照するモードでは、モードプロンプトの全文で資料を検索します。出力の形などの長い指示は、モードプロンプトよりカスタムデータ用RAGプロンプトに書くと、検索が指示の言葉に引っぱられません（カスタムデータ検索（RAG）のしくみ）。
  • 手順書や規程など、毎回読ませたい資料は、プロンプトに貼り付けずに「参照資料」としてモードに登録する方法もあります。送信のたびに自動で添付され、そのたびに添付ファイルの利用料金がかかります（モードに参照資料を付ける）。
