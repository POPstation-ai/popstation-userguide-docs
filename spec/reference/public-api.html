公開APIの仕様

対象：全ユーザー

業務システムからHTTPでPOPstationに質問を送り、回答を受け取る公開APIの、エンドポイント・認証・会話の続け方・上限・エラーの一覧です。

業務システムから、POPstationのチャットに質問を送り、回答をJSONで受け取るAPIです。APIキーの発行は業務システムから使えるAPIキーを発行するをご覧ください。

始める前に

項目内容
必要なもの管理者が「API連携」で発行したAPIキー
呼び出し先ご利用のPOPstationと同じURL（以下の例では https://<POPstationのドメイン>）。管理者は、「API連携」の一覧の上の「APIの使い方」の「呼び出し先」で、組織で使うURLを確かめられます
誰として扱われるかAPIキーの利用者が送った質問として扱われます
呼び出せる場所「システム管理」のIPアクセス制限で許可したIPアドレスからです。「すべてのIPを許可」がオンなら、どこからでも呼び出せます（下の「IPアクセス制限」）
利用料金・利用上限画面からの利用と同じです（下の「利用料金と利用上限」）
応答の形回答が全部できてから、1回でまとめて返します（少しずつ返す形には対応していません）。回答ができるまでに時間がかかりすぎると、接続が切れます（下の「上限」）

エンドポイント

用途メソッドパス
チャット（質問を送り、回答を受け取る）POST/api/v1/chat/completions
アクセストークンの取得POST/api/public/auth/token

認証

リクエストの Authorization ヘッダーに、Bearer と半角スペースに続けて、次のどちらかを指定します。

指定するもの内容
APIキー発行されたAPIキー（qtg_ で始まる文字列）をそのまま指定します
アクセストークン（JWT）APIキーと引き換えに取得する、有効期限300秒のトークンです。APIキーを失効すると、そのキーから取得したトークンもすぐに使えなくなります
Authorization: Bearer <APIキー>

アクセストークンを取得する

curl -X POST https://<POPstationのドメイン>/api/public/auth/token \
  -H "Authorization: Bearer $POPSTATION_API_KEY"

成功すると、次のJSONが返ります。

{ "access_token": "<JWT>", "token_type": "Bearer", "expires_in": 300 }

APIキーが正しくないときは、401 と {"error":"invalid_api_credential"} が返ります。

IPアクセス制限

「システム管理」のIPアクセス制限は、APIからの呼び出しにもかかります。許可していないIPアドレスから呼び出すと 403 になります。設定のしかたはIPアクセス制限を設定するをご覧ください。

  • チャットAPIと、アクセストークンの取得の両方にかかります。アクセストークンを使うときも、そのたびに判定します。許可したIPアドレスで取得したトークンでも、許可していないIPアドレスから使うと 403 になります。
  • 画面では管理者に制限がかかりませんが、APIでは、利用者のロールに関係なく制限がかかります。管理者に発行したAPIキーも同じです。
  • 判定に使うのは、POPstationにつないできた接続元のIPアドレスです。X-Forwarded-For などのヘッダーにIPアドレスを書いても、判定には使いません。
  • 業務システムのサーバーから呼び出すときは、そのサーバーがインターネットに出るときのIPアドレスを許可に加えます。
  • 「すべてのIPを許可」がオンのときは、どこからでも呼び出せます。
  • 許可を変えると、次の呼び出しから反映されます。

許可していないIPアドレスから呼び出すと、次の本文が返ります。ip は、判定に使ったIPアドレスです。このIPアドレスを許可に加えるかどうかを、管理者が判断します。

{ "error": "Source IP address is not allowed", "code": "ip_not_allowed", "ip": "<判定に使ったIPアドレス>" }

接続元のIPアドレスを判定できなかったときは、「すべてのIPを許可」がオンの組織を除いて、次の本文が返ります。

{ "error": "Source IP address could not be determined", "code": "ip_unresolved" }

チャットAPI

curl -X POST https://<POPstationのドメイン>/api/v1/chat/completions \
  -H "Authorization: Bearer $POPSTATION_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-terra",
    "messages": [{ "role": "user", "content": "この文章を3行で要約してください。…" }]
  }'

リクエストの本文

項目型必須内容
model文字列○使うAIモデルのID（下の「使えるAIモデル」）
messages配列○role（system / user / assistant のどれか）と content（文字列）の組の配列。質問として使われるのは、いちばん後ろの user の content だけです
conversationId文字列—続きの会話にするときに、前の応答で受け取った会話IDを指定します。省くと新しい会話になります
temperature・top_p・presence_penalty・frequency_penalty数値—回答の生成のしかたを調整する値です

messages にそれまでのやり取りや system を入れても、AIには送られません。前のやり取りを踏まえて質問するときは、conversationId で会話を続けます。

応答（200）

{ "content": "（AIの回答）", "conversationId": "<会話ID>" }
項目内容
contentAIの回答の本文
conversationIdこの会話のID。次のリクエストに指定すると、同じ会話の続きになります

会話を続ける

  • 1回目は conversationId を省いて送ります。応答の conversationId を、2回目以降のリクエストに指定します。
  • 会話の履歴はPOPstationが保存していて、2回目以降は、それまでのやり取りを踏まえて回答します。
  • 会話を続けられるのは、その会話を始めたAPIキーの利用者だけです。ほかの利用者・ほかの組織の会話IDや、存在しない会話IDを指定すると 404（conversation_not_found）になります。
  • 1つの会話で質問を続けられる回数に上限はありません。会話の合計の文字数が上限（下の表）を超えて 413（context_too_long）が返ったら、conversationId を省いて新しい会話を始めます。

上限

項目上限超えたとき
1回の質問の文字数200,000文字413（prompt_too_long）
1つの会話の合計の文字数（それまでのやり取りと今回の質問の合計）200,000文字413（context_too_long）
呼び出しの回数APIキーごとに1分あたり60回429（rate_limit_exceeded）
回答ができるまでの時間約2分（125秒）524（本文はJSONではありません）

回答ができるまでの時間は、回答の長さと、選んだAIモデルによって変わります。上限を超えるときは、質問を分ける、回答の長さを指定する（例：「300字以内で」）、応答の速いAIモデルを選ぶ（AIモデル一覧）、のどれかを試してください。

接続が切れても、POPstationの中では回答の処理が続き、利用料金がかかることがあります。続きの会話で送り直すときは、時間をおいてから送ってください。

文字数は UTF-16 の単位で数えます（JavaScript の String.length と同じ）。絵文字や一部の漢字は、1文字を2文字以上と数えます。

AIモデルには、モデルごとに一度に送れる文字数の上限（AIモデル一覧の「上限文字数」）もあります。画面のチャットと同じしくみです（チャットのしくみ）。

  • 上の表の範囲内でも、指定したAIモデルの上限文字数を超えた分は、古いやり取りから削って送ります。
  • 削ってもエラーにはならず、200 で回答が返ります。削ったことは応答にも示されません。
  • 1回の質問だけで上限文字数を超えたときは、質問の先頭が削られます。例：Claude Sonnet 5.5（上限文字数100,000文字）に150,000文字の質問を送ると、先頭の50,000文字はAIに送られません。
  • 長い資料を送るときは、上限文字数の大きいAIモデルを指定してください。

レート制限

項目内容
数える単位APIキーごと。アクセストークンで呼び出した分は、元のAPIキーの回数に数えます。別のAPIキーとは別々に数えます
上限1分あたり60回。時計の1分ごと（0秒から59秒）に数え直します
数えるものチャットAPIへの呼び出しのうち、認証とIPアクセス制限に通ったもの。そのあとエラーになった呼び出しも1回に数えます
超えたとき429 と {"error":"Rate limit exceeded","code":"rate_limit_exceeded"} が返ります。Retry-After の秒数だけ待ってから、もう一度送ってください

チャットAPIの成功（200）と 429 の応答には、次のヘッダーが付きます。

ヘッダー内容
X-RateLimit-Limit1分あたりの上限の回数
X-RateLimit-Remaining今の1分で、あと何回呼び出せるか
X-RateLimit-Reset次の1分が始まるまでの秒数
Retry-After再び送れるまでの秒数（429 のときだけ）

エラー

エラーのときは、HTTPのステータスと、JSONの本文が返ります。本文の error に理由、code に種類が入ります（code の無いものもあります）。ただし、本文がJSONでないエラーもあります。たとえば、回答ができるまでの時間の上限を超えたときの 524 は、本文がJSONではありません（例：error code: 524）。

HTTP本文（error / code）原因対処
400Invalid request body本文がJSONでない、model が無い、messages が空・形が正しくない、user のメッセージが無いリクエストの本文を直します
400publicApiSystemPromptRejected（text に「この内容は送信できません。送信内容を見直してください。」）質問に、APIでは送れない内容が含まれています質問の内容を見直してから送ります
401UnauthorizedAPIキーが正しくない・失効している、アクセストークンの期限が切れているAPIキーを確かめます。アクセストークンは取得し直します
403ip_not_allowed（ip に判定に使ったIPアドレス）呼び出したIPアドレスが、IPアクセス制限で許可されていません。アクセストークンの取得でも返ります管理者に、ip のIPアドレスを許可に加えてもらいます（上の「IPアクセス制限」）
403ip_unresolved接続元のIPアドレスを判定できず、IPアクセス制限で許可されているか確かめられませんでした。「すべてのIPを許可」がオンの組織では返りません。アクセストークンの取得でも返りますお問い合わせください
403Model not allowedそのAIモデルを、APIキーの利用者が使えません使えるAIモデルを指定するか、管理者に許可を依頼します
403Model not supported by the public API / model_not_supported公開APIでは使えないAIモデルです（おまかせ・画像生成のモデル）下の「使えるAIモデル」の表にあるIDを指定します
403Safety policy violation（reasons に理由）質問にNGワードや、送信をブロックする設定の機密情報が含まれています質問を直します（NGワード・機密情報のチェックを設定する）
403Credential user not foundAPIキーの利用者のアカウントが見つかりません。まだアカウントの登録を済ませていない利用者などです利用者にアカウントを登録してもらうか、別の利用者に発行し直します
404conversation_not_found会話IDが存在しないか、APIキーの利用者の会話ではありませんconversationId を省いて新しい会話を始めます
409conversation_changed同じ会話に、同時に質問を送りました前の応答を待ってから、もう一度送ります
413prompt_too_long / context_too_long上の「上限」を超えました質問を短くするか、新しい会話を始めます
422invalid_prompt質問が空白だけか、AIの回答が空でした質問を直して、もう一度送ります
429rate_limit_exceeded1分あたりの回数を超えましたRetry-After の秒数だけ待ってから送ります
500Internal server errorPOPstationの中でエラーが起きました時間をおいて、もう一度送ります
524なし（本文はJSONではありません）回答ができるまでの時間が、上の「上限」を超えました質問を分ける・回答の長さを指定する・応答の速いAIモデルを選ぶ、のどれかを試してから送り直します。接続が切れても、利用料金がかかることがあります

利用上限に関する条件に当たったときなど、AIモデルへの送信の段階で断られたときは、そのときのステータス（403 など）と本文がそのまま返ります。本文の text に理由が入ります（例：「今月のご利用料金が上限金額に達しました。」）。

使えるAIモデル

model に指定できるのは、APIキーの利用者に許可されたAIモデルです。

  • 公開APIで生成できるのは文字だけです。おまかせ（auto）と、画像を作るAIモデルは指定できません。指定すると 403（model_not_supported）になります。使うAIモデルは、下の表のIDで指定してください。
  • ユーザーグループの許可と、ユーザーごとの制限に従います（使えるモデルが決まるしくみ）。利用者のロールが管理者のときは、ユーザーグループの許可に関係なく使えます。
  • 管理者が海外リージョンのAIモデルを使わない設定にしているときは、日本リージョンのモデルだけを使えます。
  • 許可されていないモデルを指定すると 403（Model not allowed）になります。

利用料金と利用上限

  • 利用料金は、画面から質問したときと同じく、使ったAIモデルの単価で計算され、組織の利用料金に含まれます。
  • 組織の月額の利用上限と、課金グループの1人あたりの上限も、画面からの利用と同じく判定されます（利用上限と決済失敗時の扱い）。APIで使った金額も、APIキーの利用者の利用として数えます。

項目公開API
ファイルの添付できません。送れるのはテキストだけです
カスタムデータ・Web検索・URL読込使えません

セキュリティ上の注意

  • APIキーとアクセストークンは秘密の情報です。ログ・画面共有・問い合わせの内容・プログラムのソースコードに書かないでください。
  • 漏れた恐れがあるときは、管理者が「API連携」ですぐに失効し、新しいAPIキーを発行してください。
